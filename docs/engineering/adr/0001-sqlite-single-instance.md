# ADR 0001 — 继续使用单实例 SQLite

- 日期：2026-11-18
- 状态：已采纳，见 [Phase 2 公共工程摘要](../phase2-public-summary.md)

## 背景

现有基线使用文件 SQLite，配置为 `transaction_mode=IMMEDIATE`，连接超时 10 秒。预约冲突、课时余额和相同请求编号的判定与写入处于事务中。多个服务读取重叠时段或可用课时之后写入，当前并发测试依赖 SQLite 已取得写事务，而写锁错误分支也按 SQLite 行为处理。应用已有 0001–0008 迁移和历史数据升级断言。

## 决策

保留 SQLite 作为本阶段明确支持的数据库，只允许一个 web 服务实例使用本地具名卷。进程可含多个 Gunicorn worker，写事务由 SQLite 序列化。同一数据卷不得挂给同时运行的候选或旧工作室实例。迁移由同一个服务实例在 worker 启动前执行，升级前由操作者暂停写入并保留一致性备份。失败时不启动 Gunicorn，修复后重新运行同一迁移。备份恢复和降级按数据兼容性单独决定。

## 备选方案与后续门槛

PostgreSQL 有更好的部署扩展空间，但默认事务隔离不能替代 SQLite 的整库写锁。仅替换连接串或安装驱动会改变并发下的业务正确性。本阶段没有引入驱动、改迁移、改现有业务锁或承诺生产兼容。若后续采纳 PostgreSQL，应在临时独立实例验证所有迁移及旧库导入，审计时段重叠约束、锁粒度和顺序、余额扣减、幂等及重试语义，并用并发及回滚集成测试验证实际数据库行为后再改变支持范围。
